# AIHot Java 版：配置与启动指南

适用目录：D:\lyh-progrem\aihot。运行数据库为 MySQL。所有命令在项目根目录执行。

后端代码在 `backend`，前端代码在 `frontend`。如果在 IDEA 中直接运行 `AiHotApplication`，请在运行配置里将“工作目录”设置为项目根目录 `D:\lyh-progrem\aihot`，以便读取根目录的 `.env` 和 `data`。

## 1. 先准备环境

| 软件 | 要求 | 检查命令 |
|---|---|---|
| JDK | 21 | java --version |
| Maven | 3.9.x | mvn --version |
| Node.js | 建议 22.12+ 或 24；最低 20.19 | node --version |
| npm | 随 Node 安装 | npm --version |
| MySQL | 8.0 / 8.4 | 用 Navicat、Workbench 或命令行确认能登录 |

Windows 的 JAVA_HOME 应指向 JDK 根目录，不是 bin，也不是 Java 8。这个项目的 Maven 启动适配器会优先使用 JAVA_HOME。

如果你本机仍显示 Java 8，可以先在当前 PowerShell 临时指定：

```powershell
# 换成你的 JDK 21 实际安装目录。
$env:JAVA_HOME = "C:\Users\你的用户名\.jdks\你的JDK21目录"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java --version
mvn --version
```

不需要 Redis、消息队列、Python 或额外的 AI 服务进程。

## 2. 生成自己的配置

```powershell
Set-Location -LiteralPath "D:\lyh-progrem\aihot"
powershell -NoProfile -ExecutionPolicy Bypass -File .\project\scripts\setup-config.ps1
```

- 没有 .env 时：从模板创建。
- 已有 .env 时：只追加缺失配置和注释，保留你原来的 Key、模型和其他值。
- 不要直接把 .env.example 覆盖到已有 .env。
- .env 不应上传 GitHub。

用编辑器打开根目录 .env。你需要填写的地方已用中文说明。

配置文件由 Spring 按 properties 格式读取：建议值不加引号。若密码包含反斜杠，需要写成双反斜杠；容器环境变量可直接传真实值。修改配置后需要重启服务。

## 3. 创建 MySQL 数据库

用你已有的 MySQL 管理员账号登录 Navicat / Workbench，执行：

```sql
CREATE DATABASE IF NOT EXISTS aihot
CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

项目中的 project/sql/01-create-database.sql 提供同样的语句。

你可以使用已有、对这个数据库有权限的账号。若使用独立的 aihot 账号，先把以下密码改成真实密码，再执行：

```sql
CREATE USER IF NOT EXISTS 'aihot'@'localhost' IDENTIFIED BY '这里替换为你自己的强密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, INDEX, REFERENCES
ON aihot.* TO 'aihot'@'localhost';
```

Java 服务首次启动会自动创建业务表，不需要手工逐张建表。请使用独立的 aihot 数据库。

如果 MySQL 在虚拟机或另一台服务器上，连接地址与账号允许的主机需要按实际环境设置；localhost 账号示例适用于应用与数据库同机的情况。

### 必填配置

```properties
# 127.0.0.1、3306、aihot 分别是主机、端口、库名，请按实际情况修改。
DB_URL=jdbc:mysql://127.0.0.1:3306/aihot?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai
DB_USERNAME=你的数据库账号
DB_PASSWORD=你的真实数据库密码
PORT=8787
BIND_ADDRESS=127.0.0.1
# 首次建议关闭自动监控，先完成一次手动检索。
SCHEDULER_ENABLED=false
```

## 4. 可选：开启 AI 分析

默认使用阿里云百炼，也可以切换到 SiliconFlow 或 OpenRouter，只需配置其中一个。

### 在网页填写自己的 AI 接口

打开网页右上角的“AI 设置”，填写 OpenAI 兼容的 Base URL、模型名称和 API Key，再点击保存。例如百炼北京地域的 Base URL 是 `https://dashscope.aliyuncs.com/compatible-mode/v1`，模型可以填写 `qwen-plus`。保存后勾选“AI 分析”并手动检索。

这份设置只保存在当前浏览器标签页的会话存储中；每次手动检索时会随请求发送到本项目后端，由后端调用所填接口，不写入数据库。关闭标签页后需要重新填写。定时监控和监控词扫描仍使用下方服务器配置。网页保存设置不代表密钥或模型已通过真实连接测试，实际失败会降级为规则匹配。

默认允许 `dashscope.aliyuncs.com`、`dashscope-intl.aliyuncs.com`、`api.siliconflow.cn`、`openrouter.ai`、`api.openai.com`。如果需要其他可信 OpenAI 兼容服务，由管理员在服务器配置中添加域名，例如 `AI_ALLOWED_HOSTS=api.example.com`，多个域名用英文逗号分隔，然后重启服务。只允许 HTTPS 和标准端口，Base URL 以 `/v1` 结尾。Docker 本地版请在 `.env.docker.local` 配置该项并重新创建应用容器。

### 阿里云百炼

```properties
AI_PROVIDER=bailian
# 换成你新生成的百炼 API Key，不要提交到 Git 或发到聊天中。
BAILIAN_API_KEY=你自己的Key
BAILIAN_MODEL=qwen-plus
# 按量付费的北京地域 OpenAI 兼容地址。
BAILIAN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

Key、地域、Base URL 和模型权限必须匹配。默认地址适用于北京地域按量付费；其他地域请在百炼控制台查看地址，替换为以 `/compatible-mode/v1` 结尾的 OpenAI 兼容 Base URL。百炼也支持业务空间专属域名；Token Plan 和 Coding Plan 使用各自的 Key 和地址，不能与按量付费配置混用。配置完成后重启 Java 服务。实际调用可能产生费用。

### SiliconFlow

```properties
AI_PROVIDER=siliconflow
SILICONFLOW_API_KEY=你自己的Key
SILICONFLOW_MODEL=deepseek-ai/DeepSeek-V3.2
```

### OpenRouter

```properties
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=你自己的Key
OPENROUTER_MODEL=deepseek/deepseek-v3.2
```

模型 ID 必须是你账号可调用的模型。Key 未配置或在页面关闭 AI 分析时，仍会抓取真实来源，使用文字规则筛选；调用失败会显示降级状态，不会伪装成 AI 分析成功。

```properties
# 每轮最多分析 12 篇，包括被过滤及调用失败的内容。
MAX_ANALYSIS_PER_RUN=12
AI_TIMEOUT_SECONDS=35
SOURCE_TIMEOUT_SECONDS=12
MAX_AGE_DAYS=7
```

每轮还可能进行至多一次 AI 关键词扩展调用。扩展缓存保留 6 小时，文章分析缓存有效期 24 小时。频率越高、监控词越多，模型费用越高。

## 5. 安装、测试和构建

```powershell
npm ci
npm test
npm run build
```

首次需要联网下载 npm 和 Maven 依赖。构建产物：

```text
frontend/dist/
backend/target/aihot-1.0.0.jar
```

前端已打入 JAR。日常运行不需要再单独启动前端服务器。

### 启动

双击根目录的「启动AIHot.cmd」，或：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\project\scripts\start-aihot.ps1
```

启动日志出现 Started AiHotApplication 后，打开：

[http://127.0.0.1:8787](http://127.0.0.1:8787)

脚本窗口会显示服务日志，按 Ctrl+C 停止。脚本不会替你安装或启动 MySQL。

修改代码后重新构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\project\scripts\start-aihot.ps1 -Rebuild
```

也可以直接运行：

```powershell
# 确认这里的 java 是 JDK 21。
java -Xms128m -Xmx512m -jar .\target\aihot-1.0.0.jar
```

请从项目根目录运行，以便读取根目录 .env 与旧数据文件。

## 7. 验证主要功能

1. 先关闭 AI 分析开关，选择能访问的来源，搜索一个具体关键词。
2. 查看来源返回数量与错误；单个来源失败时，其余来源仍可返回。
3. 打开热点的“分析依据”，核对规则 / AI 模式与原始链接。
4. 收藏一条内容，到“我的热点库”勾选“仅收藏”确认。
5. 添加关注，设置间隔；手动扫描能查看运行记录。
6. 准备持续监控时，将 .env 的 SCHEDULER_ENABLED 改为 true 并重启。
7. 只有监控中首次通过 AI 分析的新关联内容才产生自动通知；规则匹配不会自动推送。
8. 重新启动后，MySQL 中保存的热点、关注词和收藏应继续存在。

“发现时间”是本工具保存的时间；“发布时间”来自来源，可能未知。AI 输出不是独立事实核验结果。

## 8. 可选：配置邮箱

```properties
SMTP_HOST=你的邮箱SMTP服务器
SMTP_PORT=587
SMTP_SECURE=false
SMTP_STARTTLS=true
SMTP_USER=你的发件邮箱
SMTP_PASS=邮箱SMTP授权码
NOTIFY_EMAIL=你的收件邮箱
```

若邮箱服务使用 465 + SSL，通常设置：

```properties
SMTP_PORT=465
SMTP_SECURE=true
SMTP_STARTTLS=false
```

请以邮箱服务商设置为准。SMTP_PASS 通常填授权码，不是邮箱网页登录密码。

仅监控中 AI 标为 high / urgent 的新内容发送邮件，手动搜索不发邮件。邮件失败时，站内通知仍会保留。浏览器系统通知需要在通知中心主动开启，并取决于浏览器权限。

## 9. 旧版 JSON 数据

```properties
LEGACY_IMPORT=true
```

首次启动会把 data/state.json 的监控词、通知内的文章及热点报告中的来源文章导入 MySQL，并写入导入标记。同一数据库不会在每次启动时重复导入。

原 JSON 文件不会删除。旧通知中的内容会成为历史热点，不会被当作本次新发现重新发送。旧版报告被展开为来源文章，原始报告结构仍在 JSON 中。

不希望导入时，首次启动前设置 LEGACY_IMPORT=false。旧版 Node 服务入口已移除，请使用本指南的 Java / Docker 启动方式。

## 10. 可选：Docker Compose 部署

需要 Docker 与 Compose 插件。先配置 .env，容器模式使用独立业务账号：

```properties
DB_USERNAME=aihot
DB_PASSWORD=你设置的业务数据库密码
MYSQL_ROOT_PASSWORD=另外一个管理员强密码
API_TOKEN=你生成的随机长令牌
PORT=8787
ALLOWED_ORIGINS=https://你的域名
```

这里不要将 DB_USERNAME 设为 root。Compose 会创建数据库与业务用户，并自动使用容器内的数据库地址。

```powershell
docker compose up -d --build
docker compose logs -f app
```

默认只在服务器本机暴露 127.0.0.1:8787，MySQL 不向公网映射端口。通过 Nginx 绑定你的域名并配置 HTTPS，模板见 project/deploy/nginx.conf.example。

- 域名解析到服务器公网 IP。
- 替换 Nginx 模板的域名、证书路径。
- ALLOWED_ORIGINS 填实际网页的 HTTPS 地址。
- API_TOKEN 填随机长令牌，网页首次访问时输入。
- 只运行一个应用实例。当前调度防重入锁属于进程内。
- MySQL 数据保存在 Docker 命名卷。已有卷的密码不会因修改 .env 自动更换。
- 停止服务用 docker compose down；不要附加 -v，以免删除数据库卷。

本仓库提供部署配置，未替你购买服务器、配置域名、签发证书或发布到公网。

## 11. 常见问题

| 现象 | 检查方法 |
|---|---|
| java 显示 1.8，或 UnsupportedClassVersionError | 设置 JAVA_HOME 指向 JDK 21，重新打开终端 |
| mvn 找不到 | 安装 Maven 3.9.x，将 bin 加入 PATH；必要时设置 MAVEN_HOME |
| Communications link failure / Connection refused | 确认 MySQL 已启动、地址和端口正确，虚拟机网络可达 |
| Access denied for user | 核对用户名、密码、账号允许的来源主机及数据库权限 |
| Unknown database aihot | 先执行建库脚本 |
| 8787 端口占用 | 关闭这个项目原有服务，或修改 PORT；开发代理也要同步修改 |
| Maven/npm 下载失败 | 检查网络、DNS 和本机镜像设置；离线缓存不足时无法完成首次构建 |
| 页面正常但接口报错 | 检查 Java 日志、MySQL 配置；开发时确认后端与代理端口一致 |
| 页面提示访问令牌错误 | 输入 .env 的 API_TOKEN；修改配置后重启 |
| 某来源返回 403、429、超时、验证页 | 查看“来源与运行”，暂时取消该来源或稍后重试 |
| AI 降级 | 检查 Key、模型 ID、额度与服务商网络可用性 |
| 没有通知 | 检查调度开关、关注词是否启用，以及新内容是否通过 AI 分析 |
| 邮件不发送 | 检查 SMTP 授权码、端口和 TLS 配置，确认热点为 high/urgent |
| 修改前端后界面没变化 | 重新 npm run build 并重启，必要时浏览器强制刷新 |

### API 健康检查

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health
```

开启访问令牌后，其他接口需要请求头 X-AIHot-Token；/api/health 不需要。具体接口见 api-java.md。
