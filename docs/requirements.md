# AIHot 需求沉淀

更新日期：2026-07-08

## 目标

AIHot 是一个轻量级 AI 热点与关键词监控工具。用户输入关键词或关注范围后，系统定时从公开来源抓取候选内容，并通过 AI 判断相关性、仿冒/钓鱼风险和热点强度，最终在 Web 页面中展示通知和热点报告。

## 当前项目现状

- 技术栈：Node.js 18+、原生 HTTP server、原生前端 HTML/CSS/JavaScript、Node 内置 `node:test`。
- 当前运行入口：`server.js`，使用 CommonJS 模块。
- 当前数据存储：本地 JSON 文件 `data/state.json`。
- 当前公开来源：Google News RSS、Hacker News Algolia、GitHub Search。
- 当前 AI 接入：可切换 AI Provider，默认使用 SiliconFlow Chat Completions API 接入 DeepSeek；保留 OpenRouter 兼容。未配置当前 Provider 密钥时使用本地启发式规则回退。
- 当前前端：单页工作台，支持关键词监控、热点范围、浏览器通知和手动刷新。

## 已发现约束

- `README.md`、部分源码字符串和测试用例存在中文乱码，需要在后续需求中确认是否纳入修复范围。
- 仓库内同时存在 `server.js`/`src/jobs.js` 的 CommonJS 路线，以及 `src/app.js` 的 ESM 风格应用封装；后续开发前需要确认保留哪条主线。
- `mcp-tokens.ps1` 看起来包含真实 API 密钥，后续不得在文档、提交信息或回复中暴露具体值。
- 本轮工具发现尚未暴露 Context7 的 `resolve-library` / `get-library-docs` 类工具；已尝试通过 Codex CLI 注册全局 MCP server `context7`，但 `mcp list` / `mcp get context7` 尚未确认注册成功。

用户确认把此前截图中的国内信息源也加入项目。本轮新增：

接入原则：

- 所有新增内容仍需经过 AI 相关性与仿冒/钓鱼识别，再进入通知或热点报告。

## Sprint 2026-07-14 筛选与排序

用户确认本轮不采用过于工程化的数据字段筛选，而是采用更贴近日常使用的结果筛选与排序方式。筛选和排序主要作用于“命中通知 / 热点结果”列表，关键词监控管理区保持轻量，只保留创建、启用/暂停和删除等基础管理动作。

### 筛选维度

| 维度 | 可选值 | 说明 |
| --- | --- | --- |
| 信息来源 | Google News / Bing / DuckDuckGo / Hacker News / GitHub / 搜狗微信 / B 站 / 微博 | 按来源过滤结果 |
| 重要性 | urgent / high / medium / low | 按 AI 判定的重要性等级过滤 |
| 关键词 | 用户配置的所有关键词 | 按监控关键词过滤 |
| 时间范围 | 最近 1 小时 / 6 小时 / 24 小时 / 7 天 / 全部 | 按系统发现时间过滤 |

### 排序方式

| 排序 | 规则 | 说明 |
| --- | --- | --- |
| 热度综合 | 综合点赞、转发、浏览量、来源分数等指标 | 社交热度最高的排在前面 |
| 相关性 | 按 AI 评分排序 | 与关键词最相关的排在前面 |
| 最新发布 | 按帖子/文章原始发布时间排序 | 最新发布的排在前面 |
| 最新发现 | 按系统抓取或入库时间排序 | 最新被系统发现的排在前面 |
| 重要程度 | 按 AI 判定的重要性排序 | 最紧急重要的排在前面 |

### 重要性映射

当前后端已有 `urgency` 数字字段，但还没有 `urgent/high/medium/low` 文本等级。本轮按以下规则映射：

| 等级 | urgency 范围 |
| --- | --- |
| urgent | 80-100 |
| high | 60-79 |
| medium | 40-59 |
| low | 0-39 |

### 默认行为

- 默认排序使用“重要程度优先”，同等级内按“最新发现”倒序排列。
- 筛选控件默认不收窄结果，即信息来源为全部、重要性为全部、关键词为全部、时间范围为全部。
- 页面需要保留当前雷达/信号工作台视觉，不改成通用后台表格页。

## Sprint 2026-07-14 结果卡片信息增强

用户确认结果卡片需要帮助人工更快判断信息价值，减少跳转到原始网站后再补充判断的成本。本轮按“原始描述优先，AI 摘要和判断理由放在展开详情里”的方式实现。

### 默认展示

| 信息 | 说明 |
| --- | --- |
| 标题 | 帖子、文章或视频标题 |
| 来源 | Bing / B 站 / 微博 / Hacker News 等 |
| 关键词 | 命中的监控关键词 |
| 重要性 | urgent / high / medium / low |
| 相关性 | AI 相关性评分或置信度 |
| 热度 | 来源热度或系统综合热度 |
| 发布时间 | 原始内容发布时间 |
| 发现时间 | 被 AIHot 抓取或入库的时间 |
| 原始描述 | 来源抓取到的描述或摘要，默认优先显示 |
| 查看来源 | 跳转原始网站 |

### 展开后展示

| 信息 | 说明 |
| --- | --- |
| AI 摘要 | AI 生成或判断出的内容摘要 |
| AI 判断理由 | 为什么相关、为什么值得看、是否有噪声 |
| 风险提示 | 是否疑似标题党、营销、仿冒、钓鱼 |
| 互动数据 | 点赞、评论、转发、播放量、star 等，有则显示 |
| 来源发布时间 | 原始平台发布时间 |
| 系统抓取时间 | AIHot 发现或入库时间 |
| AI Provider | SiliconFlow / OpenRouter / local fallback |
| 标签 | 官方、教程、发布、争议、测评、融资、开源等 |

### 实现边界

- 第一版不额外跳转抓取原站详情页，只展示当前数据结构已经有的字段。
- 没有互动明细时使用现有 `scoreHint`、`heat`、`urgency` 等综合分数作为热度提示。
- 对缺失字段稳定降级，不显示空白信息块。

## Sprint 2026-07-14 统一监控词、全网搜索与实时通知

用户确认新增三个体验需求：

1. 关键词监控和热点范围在产品概念上合并为一个“监控词”，页面只保留一个小窗口用于添加和开关管理。
2. 新增搜索功能，用户输入特定关键词后可以即时搜索全网公开来源信息，不必先保存为监控词。
3. 页面侧边增加通知面板，类似消息通知列表，通过 WebSocket 实时推送新命中和热点通知。

### 统一监控词

- 一个监控词同时用于关键词命中通知和热点发现。
- 添加监控词时，系统自动创建或复用同名关键词监控和热点范围。
- 监控词列表以开关形式展示启用/暂停状态。
- 页面不再把“监控关键词”和“热点范围”拆成两个输入区。
- 保留现有底层 `monitors` 和 `scopes` 数据结构，作为兼容实现，不在本轮迁移历史数据。

### 全网搜索

- 搜索输入不写入监控配置。
- 搜索调用现有公开信息源聚合能力，返回标题、来源、发布时间、热度、摘要和原始链接。
- 搜索失败的来源需要进入错误提示，不影响其他来源结果展示。
- 搜索结果沿用当前结果卡片的信息层级和视觉风格。

### WebSocket 实时通知

- 浏览器打开页面后连接 WebSocket。
- 后端产生新的命中通知或热点报告时，向已连接页面推送事件。
- 侧边通知面板展示最近实时消息，包含标题、关联关键词/范围、摘要和时间。
- WebSocket 断开后前端自动重连；原有 `/api/state` 轮询继续保留作为兜底。

### 验收标准

- 页面只有一个监控词输入和开关列表，不再要求用户分别配置关键词和热点范围。
- 可以通过搜索框即时搜索公开来源，并展示结果。
- 后端提供 WebSocket 推送，新命中和新热点会进入侧边通知面板。
- 文档、实现和测试验证同步更新。
