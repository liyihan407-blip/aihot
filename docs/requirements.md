# AIHot 需求沉淀

更新日期：2026-07-08

## 目标

AIHot 是一个轻量级 AI 热点与关键词监控工具。用户输入关键词或关注范围后，系统定时从公开来源抓取候选内容，并通过 AI 判断相关性、仿冒/钓鱼风险和热点强度，最终在 Web 页面中展示通知和热点报告。

## 当前项目现状

- 技术栈：Node.js 18+、原生 HTTP server、原生前端 HTML/CSS/JavaScript、Node 内置 `node:test`。
- 当前运行入口：`server.js`，使用 CommonJS 模块。
- 当前数据存储：本地 JSON 文件 `data/state.json`。
- 当前公开来源：Google News RSS、Hacker News Algolia、GitHub Search。
- 当前 AI 接入：可切换 AI Provider，默认使用 SiliconFlow Chat Completions API 接入 DeepSeek；保留 OpenRouter 兼容。未配置当前 Provider 密钥时使用本地启发式规则回退。
- 当前前端：单页工作台，支持关键词监控、热点范围、浏览器通知和手动刷新。

## 已发现约束

- `README.md`、部分源码字符串和测试用例存在中文乱码，需要在后续需求中确认是否纳入修复范围。
- 仓库内同时存在 `server.js`/`src/jobs.js` 的 CommonJS 路线，以及 `src/app.js` 的 ESM 风格应用封装；后续开发前需要确认保留哪条主线。
- `mcp-tokens.ps1` 看起来包含真实 API 密钥，后续不得在文档、提交信息或回复中暴露具体值。
- 本轮工具发现尚未暴露 Context7 的 `resolve-library` / `get-library-docs` 类工具；已尝试通过 Codex CLI 注册全局 MCP server `context7`，但 `mcp list` / `mcp get context7` 尚未确认注册成功。

## 需求范围

### 已有能力

- 用户可以创建关键词监控项。
- 用户可以创建热点范围。
- 系统可以手动或定时刷新抓取任务。
- 系统可以根据 AI 或本地规则生成通知和热点报告。
- 页面可以展示运行状态、来源错误、通知列表和热点报告。

- 是否需要调整 AI API 提供商、模型、提示词或响应格式。
- 是否需要从信息源候选清单中挑选本次优先接入的数据源。
- 是否需要新增持久化方式、鉴权、部署方式或 UI 改版。

### 本次开发范围

用户确认继续开发后，本次先按技术方案的第一阶段推进：

- 新增 Bing 信息源，优先使用无需 API Key 的公开 RSS/公开页面能力。
- 新增 DuckDuckGo 信息源，优先使用无需 API Key 的公开 HTML 搜索能力。
- 保留现有 Google News、HackerNews、GitHub 信息源。
- 不在本次接入 Twitter、微博、B 站、搜狗等可能涉及登录态、反爬或平台规则风险的信息源。
- 不引入新依赖，继续使用 Node.js 内置 `fetch` 和现有解析工具。

### 本轮继续开发补充

- 网页版是第一优先级，需要修复中文乱码并确保核心操作可用。
- 前端页面要保持独特识别度，继续采用雷达/信号工作台视觉，而不是通用后台模板。
- SiliconFlow + DeepSeek 是当前默认 AI 接入主线；未配置 `SILICONFLOW_API_KEY` 时可以演示，但必须明确这是本地启发式回退。OpenRouter 保留为可选兼容 Provider。
- Agent Skill 必须在网页版可用后再交付，放在项目 `skills/` 目录中，供其他 AI 复用监控和热点发现流程。

### 国内信息源补充

用户确认把此前截图中的国内信息源也加入项目。本轮新增：

- 搜狗微信：用于微信公众号文章内容发现。
- B 站：用于国内科技视频与创作者内容发现。
- 微博：用于国内热点和社交讨论发现。

接入原则：

- 第一版优先做公开候选内容发现，不保存 Cookie，不模拟登录，不绕过验证码。
- 涉及官方付费、OAuth、登录态或平台规则限制的能力，先在文档中标记，后续由用户确认凭据和合规边界后再增强。
- 国内源失败不能影响其他信息源扫描，页面需要继续展示可用结果和源级错误。
- 所有新增内容仍需经过 AI 相关性与仿冒/钓鱼识别，再进入通知或热点报告。

## 非功能需求

- 开发前必须通过 Context7 MCP 获取相关库/API 的最新文档，避免使用过时代码。
- 任何涉及外部 API 的改动，都需要记录使用的文档来源、关键参数和版本/日期。
- 代码改动前必须先更新或补充 Markdown 需求与方案。
- 代码实现后必须运行现有测试；如新增重要行为，应补充测试。
- 不在仓库中提交真实 API Key、Token 或个人凭据。
- 必须提交 `.env.example` 作为环境变量模板；真实 `.env`、`.env.*` 和 `mcp-tokens.ps1` 必须保持在 Git 忽略范围内。
- 不做无关重构；除非用户确认，否则只改本次需求相关文件。
